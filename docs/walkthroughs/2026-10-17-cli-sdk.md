## 中文

已在 fork 工作区实现 `@jacobinwwey/stackprism@0.1.0`，未提交、推送或发布 npm。使用说明见 [CLI / SDK README](https://github.com/Jacobinwwey/stackprism/blob/integration/agent-cli-sdk/packages/stackprism/README.md)。

修复内容：

- 将 TypeScript 固定到 `~5.9.3`，修复当前 `vue-tsc` 与 TypeScript 7 的内部入口不兼容；测试编译改用已有 esbuild。保留 Bun 锁文件，未修改用户原有未跟踪的 `package-lock.json`。
- 补齐 `PageSupport.reasonCode`，让 popup 的既有本地化调用取得实际原因。清除阻塞检查的未使用导入／参数；翻译生成脚本改为 ESM 和相对自身的输出路径。
- 修复正文 `jQuery.` 被文件名正则识别为 jQuery 的误判。该规则限制到资源模式匹配，同时保留全局变量检测和版本提取；扩展与 SDK 均有正负例回归。

实现边界：

- `src/core` 承载从原实现移动的页面检测、规则展开与预编译。原扩展注入入口继续调用同一函数；没有复制第二套匹配算法。
- `detectPage(page)` 读取调用方页面；`scanUrl(url)` 完成独立浏览器启动、导航、主文档响应头检测、页面检测与清理。CLI 调用 `scanUrl`。
- 加入检测预算、AbortSignal、结构化错误、导航竞争检测、JSON 报告和固定退出码。相同 URL 重载也会被拒绝；Playwright 执行上下文销毁可能先于导航事件，因此同时识别该底层错误。
- 包含 ESM SDK、CLI shebang/bin、类型声明、MIT 许可证和预编译规则。资源路径基于 `import.meta.url`，与工作目录无关。规则未压缩约 19.6 MB，完整 npm tarball 约 1.53 MB。

## English

Implemented fork-local `@jacobinwwey/stackprism@0.1.0`; no commit, push or npm publication. See the [CLI / SDK README](https://github.com/Jacobinwwey/stackprism/blob/integration/agent-cli-sdk/packages/stackprism/README.md).

Defects fixed:

- Pinned TypeScript to `~5.9.3` for compatibility with the current vue-tsc internal entry point. Formatter tests use the existing esbuild dependency. Updated Bun's lockfile; preserved the user's pre-existing untracked `package-lock.json`.
- Added actual `PageSupport.reasonCode` values expected by popup localization. Removed blocking unused imports/arguments. Converted the translation generator to ESM with a module-relative output path.
- Fixed the jQuery filename regex matching prose such as `jQuery.`. Pattern matching now targets resources while preserving runtime globals and version extraction; extension and SDK positive/negative regressions cover it.

Implementation:

- Moved browser detection, normalization and precompilation into `src/core`; the extension injection entry calls the same function. No second matching algorithm.
- `detectPage(page)` inspects caller-owned pages. `scanUrl(url)` owns browser launch, navigation, main-document header detection, page inspection and cleanup. The CLI invokes that complete operation.
- Added budgets, AbortSignal, structured errors, navigation-race detection, JSON reports and stable exit codes. Same-URL reloads are rejected. Playwright context-destruction errors can precede navigation events, so both signals are recognized.
- Ships ESM, CLI shebang/bin, public declarations, MIT license and precompiled rules. Assets resolve through `import.meta.url`, independently of cwd. Rules occupy approximately 19.6 MB; the npm tarball is approximately 1.53 MB.

Browser checks cover runtime/resource/meta/header/version detections, cookie-value omission, prose negatives, redirects, HTTP 404, navigation failure, timeout, cancellation, ownership, concurrent page isolation, same-URL reloads and CLI streams/exit codes. Execution environment was Windows, Node 22.19.0 and installed Chrome. Firefox, Linux, macOS and extension UI end-to-end behavior were not verified.

Rules version: `1.3.90`. Content SHA-256: `a6228256f7d91f7e5160c21d8cccab0ad0034fbadd2302eeab3aa4fc1c37039c`. Use the hash to distinguish fork rule edits that retain the upstream version.

Remaining limits: inherited Chinese evidence/categories; confidence grades are not probabilities; no continuous observation, frame internals, subresource headers or supplementary fetching. `detectPage` does not refetch headers. Cancellation cannot forcibly interrupt hostile synchronous code in a caller-owned page. Synchronous filtering means the budget is not a hard real-time bound. Existing extension large-chunk and inlineDynamicImports warnings remain.

Next priority: labeled real-site regression fixtures and false-positive/false-negative analysis before dynamic observation or richer evidence fields. An MCP adapter alone does not improve detection accuracy.
