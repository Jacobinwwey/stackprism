# CLI / SDK implementation

## 中文

目标：先修复已复现的 TypeScript 工具链缺陷，再交付复用现有检测逻辑的可安装 Node SDK 和单 URL CLI。不实现 MCP、爬站、静态 HTML 模拟器或独立规则引擎。

选择：共享浏览器内检测函数、规则展开和构建期预编译。SDK `detectPage(page)` 读取调用方已有 Playwright 页面；`scanUrl(url)` 管理自己的浏览器和单次导航，CLI 调用该完整操作。首版检测主文档与当前页面运行时／DOM／资源，明确不覆盖 iframe 内部、持续动态监测、包体补充采样和 WordPress 主动读取。

替代方案：直接桥接扩展最少移动代码，但会继承 tab 缓存和 UI 完成语义；静态 HTML runner 更轻，但缺少真实运行时和选择器语义。当前选真实浏览器复用，代价是用户需要安装 Chrome／Chromium。

边界：SDK 不接管调用方浏览器；CLI 使用隔离上下文并在成功／失败后关闭。仅 HTTP(S)，拒绝带身份凭据的输入 URL；这是本地开发工具，允许显式 localhost，不声称可直接作为多租户公网服务。页面事实不可信，报告保留继承的证据与置信度，并输出规则版本、采集范围和明确错误。首版不把现有文本证据包装成完整证据图。

## English

Goal: repair the reproduced TypeScript toolchain incompatibilities, then deliver an installable Node SDK and single-URL CLI reusing the existing detector. MCP, crawling, static HTML simulation, and a second matcher are out of scope.

Decision: share browser detection, rule expansion, and build-time preprocessing. `detectPage(page)` inspects a caller-owned Playwright Page. `scanUrl(url)` owns its browser and single navigation; the CLI invokes that complete operation. Initial coverage is the main document and current runtime/DOM/resources. Frame internals, ongoing observation, bundle sampling, and active WordPress requests remain explicitly unobserved.

Alternatives: an extension bridge moves less code but inherits tab-cache/UI completion semantics. A static runner is lighter but cannot preserve runtime and selector semantics. Reusing a real browser avoids those divergences, at the cost of requiring installed Chrome/Chromium.

Boundaries: the SDK leaves caller-owned browsers open; the CLI closes its isolated context on success/failure. Only HTTP(S), with credential-bearing input URLs rejected. Explicit localhost is allowed for this local developer tool; it is not a multi-tenant public scanning service. Page content is untrusted. Reports preserve inherited evidence/confidence and expose rule version, coverage, and explicit errors rather than claiming a complete provenance graph.
